## 2. Changes Applied On This Branch

1. **Created `ios/App/App/PrivacyInfo.xcprivacy`** — app-level privacy manifest declaring data types from ASC nutrition labels. Apple has required this for App Store submissions since May 2024; without it Apple's automated submission check warns or rejects.
2. **Updated `.github/workflows/ios-build.yml`** — preserves `PrivacyInfo.xcprivacy` across `cap add ios` scaffold regeneration (same pattern already in place for `Info.plist`).
3. **Created this report (`ios/APPLE-SUBMISSION-READY.md`)** — single-page submission readiness reference.

No code paths, runtime behavior, or product functionality were modified. The diff is restricted to a new XML manifest, a CI YAML edit, and a Markdown report.

## 3. Open Items Kat Must Resolve Manually

### HIGH — verify before submission
1. **Privacy page content** — open `https://noesis-io.us/legal/privacy/health` in a real browser (Chrome/Safari, JS enabled). The page should display health-specific privacy content: HIPAA notice, BAA availability, PHI handling, 7-year retention, AES-256-GCM. If it falls back to the generic four-suite marketing copy, Apple will reject under Guideline 5.1.1.
2. **Marketing site positioning vs. ASC framing** — the live marketing site's `<meta description>` reads *"NOESIS Health for consumers"* while the ASC submission frames the app as B2B SaaS *"NOT a consumer health app"*. Apple reviewers cross-check. Decision needed before submit: either (a) update marketing meta to align with B2B framing, or (b) re-frame ASC notes if the consumer positioning is the actual product intent.
